# 🌩️ GCP Infrastructure Project (Terraform + GKE)

This project provisions a complete Google Cloud Platform (GCP) environment using **Terraform**, including networking, IAM, virtual machines, GKE cluster, and a simple Kubernetes application deployment.

---

## ⚙️ Deployment Steps

### 1. **Authenticate to GCP**
```bash
gcloud auth application-default login
```

### 2. **Initialize Terraform**
```bash
terraform init
```

### 3. **Validate and Plan**
```bash
terraform validate
terraform plan -out=tfplan
```

### 4. **Apply Infrastructure**
```bash
terraform apply tfplan
```

### 5. **Connect to GKE Cluster**
```bash
gcloud container clusters get-credentials private-gke-cluster --region us-central1
```

### 6. **Deploy Kubernetes Workloads**
```bash
kubectl apply -f K8s/
```

## 🧹 Clean Up

To destroy all created resources:
```bash
terraform destroy
```

If the GKE cluster is stuck or partially deleted, manually clean instance groups:
```bash
gcloud compute instance-groups managed list
gcloud compute instance-groups managed delete <group-name> --zone=<zone> --quiet
```

## 🏗️ Components Overview

| Component | Description |
|------------|-------------|
| **Network.tf** | Creates custom VPC, subnets (management & restricted), and NAT gateway |
| **management_vm.tf** | Deploys a private management VM for operations and testing |
| **gke.tf** | Builds a private GKE cluster with private nodes and authorized networks |
| **iam.tf** | Manages IAM roles and service accounts for secure access |
| **K8s folder** | Contains Kubernetes manifests for the sample application |
| **terraform-key.json** | Service account key used for Terraform authentication (keep private!) |

## 🧠 Best Practices Followed

- ✅ Private GKE cluster with private nodes  
- ✅ Least privilege IAM configuration  
- ✅ Separate subnets for management and workloads  
- ✅ Infrastructure as Code (IaC) via Terraform  
- ✅ Modular and clean file structure  
- ✅ Kubernetes Ingress for public exposure (no separate LB.tf)
